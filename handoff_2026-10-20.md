## 6. Gotchas learned today

- **Folder names carry a phase prefix:** `runs/train_…`, `runs/test_…`, `runs/debug_…`. Folders
  are named to the second, so two runs of the same name in one second share a folder.
- **The test job takes the training folder** (`run = /radraid2/.../train_…`); target and fold
  come from its name. Its `Process_` trajectories (about 5 MB a slice) stay on the H100's `/home`.
- **Docker on the box needs `--shm-size=8g`** (or `--workers 0`) for anything with DataLoader
  workers; the default 64 MB `/dev/shm` dies with "No space left on device". Condor jobs ask
  for 8 GB already.
- **`condor_wait` chains** must run inside `screen` (or `nohup`), from `condor/`, with `C` set in
  that shell.
- **`git pull` on 14958 while DAGs run:** later DAG nodes start with the checkout as it is then.
  Every change today kept fold jobs' arguments and paths as they were; keep it that way.
- **Never rerun the Tmax staging** (`ctp_only_stage_home.sub` without `target`) while a job
  runs: it replaces gan_bpm's code under it. The rCBF and all-data staging only add files.
- **The repo tracks `__pycache__`:** don't delete or add `.pyc` files.
- **The laptop runs nothing** (memory: compute workflow). Syntax checks only; everything else is
  a paste or a Condor job on the box.
